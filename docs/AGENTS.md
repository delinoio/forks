# Instructions for `docs/`

- Follow the root `AGENTS.md`.
- Keep `docs/README.md` synchronized when documentation is added, removed, renamed, or regrouped.
- Keep the fork catalog synchronized when a fork is added, removed, relocated, or updated to a new upstream revision.
- Keep project indexes and domain contracts concise and decision-focused.
- Record each fork's upstream repository and imported revision, owned paths, fork purpose and local differences, synchronization approach, and license or attribution obligations in its project index.
- Record selected behavior, ownership, interfaces, committed technology choices, and explicit exceptions without long comparative prose.
- Update affected contracts in the same change as contract-relevant decisions.
- Catalog documentation policy files in `docs/README.md` instead of copying broad path lists into unrelated contracts.
